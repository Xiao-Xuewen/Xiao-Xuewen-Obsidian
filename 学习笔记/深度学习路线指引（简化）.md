### 阶段 3：领域背景——显微成像与自监督去噪

**目标**：看懂 SN2N 的"上下文"。两件事：① 显微成像的基本物理（否则不知道"噪声从哪来、超分辨是什么"）；② 自监督去噪的方法谱系（否则不知道 SN2N 好在哪）。

**学习内容**

**A. 显微成像基础

- 荧光显微镜原理、PSF 与衍射极限、信噪比与光子预算（光漂白/光毒性——为什么活细胞成像要"省光子"）
- 三大超分辨路线的概念级理解：**SIM**（结构光照明，SN2N 主要实验平台）、**STED**（受激发射损耗）、**STORM/PALM**（单分子定位）
- 学会用 [Fiji (ImageJ)](https://fiji.sc/) 打开并查看一张 tif 堆栈（调 LUT、调对比度、播放时间序列）

**B. 自监督去噪谱系

| 顺序 | 论文 | 一句话核心 | 读的重点 |
| --- | --- | --- | --- |
| 1 | **Noise2Noise**（Lehtinen et al., ICML 2018, [arXiv:1803.04189](https://arxiv.org/abs/1803.04189) | 用两幅独立噪声图互为目标即可学习去噪，L2 损失下最优解与干净标签一致 | 理论证明（正是数学系的主场）；它需要"成对独立噪声"这一限制 |
| 2 | **Noise2Self**（Batson & Royer, ICML 2019, [arXiv:1901.11365](https://arxiv.org/abs/1901.11365) | 利用数据不同维度间的统计独立性，自划分输入/目标（J-invariance） | 掩码思想；如何"单图"实现 |
| 3 | **Noise2Void**（Krull et al., 2019, [arXiv:1811.10980](https://arxiv.org/abs/1811.10980) | blind-spot 策略：遮住目标像素自己，用邻域预测它 | blind-spot 假设什么时候失效 |
| 4 | **SN2N**（本目标论文） | 对角重采样+傅里叶插值造 N2N 对 + 自约束损失 + Patch2Patch | 相对前三篇解决了什么问题；实验如何设计 |

## 三、贯穿全程的三项制度

### 1. Git 工作流（从第 1 天开始，天天用）

- **每天至少一个 commit**，message 格式：`类型: 摘要`，类型 = `feat`（新功能）/ `fix`（修 bug）/ `docs`（笔记）/ `exp`（实验）；例：`exp: P2Pmode=0 消融，PSNR 27.3`
- 所有作业与实验进仓库；**数据文件、模型权重、大 tif 一律进 `.gitignore`**（在 README 里写清下载方式即可）
- 分支习惯：试新想法开 `dev-*` 分支，跑通再合回 `main`
- 每周五 push 一次完整进度，师兄周日 review，周一给评论
- 禁止事项：`git push -f` 到 main；commit message 写"update"、"修改"；把几百 MB 数据 push 上来

### 2. Obsidian 笔记体系（第 1 周建好目录，之后只用不建）

```text
dl-learning-journey/（与 GitHub 仓库同构，直接 push）
├── 00-收集箱/          # 日报式的碎片记录，每周整理进下面各分区
├── 01-学习笔记/        # Python / PyTorch / DL 原理，一篇一个概念
├── 02-文献笔记/        # 按模板：N2N、N2Self、N2V、SN2N……
├── 03-代码笔记/        # 源码走读、调试记录、API 用法
├── 04-复现日志/        # SN2N 复现全程流水账（阶段 4 起每日更新）
├── 05-周报/            # 每周五：本周做了什么、卡在哪、下周计划
└── 99-附件/            # 图片等
```

- 要求：公式一律用 LaTeX 手写（禁止截图公式）；代码块标注语言；每周至少 3 篇成文笔记
- **周报制度**：每周五发师兄，三段式——本周完成 / 遇到的问题 / 下周计划。这是师兄判断进度与卡点的唯一可靠依据，**宁多勿少**

## 四、常见坑预警

| 坑 | 症状 | 预防/解法 |
| --- | --- | --- |
| CUDA 与 PyTorch 不匹配 | `torch.cuda.is_available()` 为 False | 按显卡驱动支持的最高 CUDA，去 [PyTorch 历史版本](https://pytorch.org/get-started/previous-versions/) 找对应安装命令 |
| VS Code 用错解释器 | 明明装了包却 `ModuleNotFoundError` | 右下角状态栏选择 conda 环境对应的 Python |
| 中文/空格路径 | 各种诡异 IO 报错 | 代码和数据放纯英文路径，路径参数加引号 |
| 数据进 git | 仓库几个 GB，push 半天失败 | `.gitignore` 第一天就写好；误提交用 `git rm --cached` |
| Jupyter 内核不对 | notebook 里的 import 和终端不一致 | Kernel → Change Kernel → 选对应环境 |
| 训练 loss 不降 | NaN 或水平线 | 依次查：学习率（先试 1e-4）、数据归一化（显微图像 16-bit 常见 0–65535，必须归一化）、标签错位 |
| 显存爆炸 (OOM) | `CUDA out of memory` | 减 batch size / 减 patch 大小 / 混合精度；3D 任务先算显存再训 |
| 盲目等训练 | 一跑几小时发现参数写错了 | 先用 1 个 batch + 2 个 epoch 的"冒烟测试"跑通全流程，再开正式训练 |
| 环境越装越乱 | conda 环境互相污染 | 一个项目一个环境；环境导出 `conda env export > environment.yml` 存进仓库 |
